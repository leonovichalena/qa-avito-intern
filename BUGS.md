# Отчет о найденных багах

## Общая информация
- **Дата тестирования**: 16.11.25
- **Версия API**: 1 / 2
- **Тестовое окружение**: localhost

## Найденные баги

### [BUG-001] Несоответствие ожидаемого статус-кода при создании объявления c invalid seller_id
- **Описание**: При создании объявления с seller_id вне диапазона 111111-999999, возвращается статус 200 вместо ожидаемого 400
- **Шаги воспроизведения**:
  1. Отправить POST запрос на /api/item с seller_id = 10 или 999999999999999
  2. Проверить статус-код ответа
- **Ожидаемый результат**: Status code: 400
- **Фактический результат**: Status code: 200
- **Серьезность**: Средняя
- **Приоритет**: Средний

### [BUG-002] Некорретный формат выдачи ответа
- **Описание**: Объявление создано и получено, но ответ приходит в виде массива, что является ошибкой, поскольку по ID объявления не может быть массива данных, а только одно объявление
- **Шаги воспроизведения**:
  1. Отправить POST запрос на /api/1/item 
  2. Проверить формат ответа
- **Ожидаемый результат**: Status code: 200, ответ содержит поле id соотвествующий пункту 1, Ответ приходит в виде объекта
- **Фактический результат**: Ответ приходит в виде массива, а не объекта
- **Серьезность**: Средняя
- **Приоритет**: Средняй

### [BUG-003] Несоответствие ожидаемого статус-кода при получении объявлений несуществующего продавца
- **Описание**: При запросе объявлений несуществующего продавца приходит неверный статус-код
- **Шаги воспроизведения**:
  1. Отправить GET запрос на /api/1/756678/item?=756678
  2. Проверить статус-код ответа
- **Ожидаемый результат**: Status code: 404
- **Фактический результат**: Status code: 200
- **Серьезность**: Средняя
- **Приоритет**: Средняй

## Рекомендации
1. Реализовать по стандарту ответы с правильными статус-кодами от бекенда
2. Реализовать единообразные форматы ответов для данных (массивы / объекты)
